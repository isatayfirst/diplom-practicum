# BACKEND.md

Бэкенд: стек, модель данных, API, вход, экспорт.

## Стек
Next.js (App Router, TypeScript) + Supabase + деплой на Vercel.
Проект Supabase `practicum-mvp` уже существует: схема, RLS, `tasks_public` без ответов.

**ВАЖНО:** перед любой работой с базой в будущих шагах сначала осмотри существующие таблицы и RLS (только чтение). Ничего не пересоздавай. Изменения схемы только миграциями в `supabase/migrations`.

## Модель данных
Фактическая схема по осмотру базы 2026-11-05 (миграции `practicum_schema_v1`, `replace_sort_filter_with_functions`, `students_personal_code`, `classes_study_group`, `tests`). Число строк указано без тестовых данных приёмки.

| Таблица | Строк | Колонки |
|---|---|---|
| `classes` | 0 | `id`, `code` (unique), `label`, `active`, `created_at`, `study_group` (NOT NULL, без значения по умолчанию: `experimental` / `control`) |
| `students` | 0 | `id`, `class_id`, `number` (> 0), `created_at`, `personal_code` (NOT NULL, 5 знаков `A–Z`, `0–9`, unique внутри класса) |
| `datasets` | 4 | `id`, `key` (unique), `label`, `name`, `source_url`, `snapshot_date`, `data` (jsonb) |
| `tasks` | 10 | `id`, `order_no` (unique), `skill` (read / calc / functions / conclude), `dataset_id`, `statement_kk`, `answer_type` (number / choice / text), `correct_value`, `tolerance`, `options`, `correct_option`, `rubric` |
| `attempts` | 0 | `id`, `student_id`, `task_id`, `answer_raw`, `is_correct` (может быть null), `time_spent_ms`, `created_at`; индекс `(student_id, task_id)` |
| `text_scores` | 0 | `attempt_id` (PK), `score` (0–2), `scored_at` |
| `tests` | 2 | `id`, `kind` (unique: `pretest` / `posttest`), `created_at`. Две строки созданы миграцией |
| `test_questions` | 0 | `id`, `test_id`, `position` (> 0, unique вместе с `test_id`), `statement_kk`, `options` (jsonb-массив строк). Эталона здесь нет |
| `test_question_keys` | 0 | `question_id` (PK), `correct_option`. Эталон отдельно от вопроса; читается только при подсчёте баллов (шаг 7) |
| `class_tests` | 0 | `class_id`, `test_id` (PK пара), `open` (по умолчанию false). Нет строки = тест закрыт. Переключатель — шаг 7 |
| `test_answers` | 0 | `id`, `student_id`, `question_id`, `answer_raw`, `time_spent_ms`, `created_at`; unique `(student_id, question_id)` |
| `test_sessions` | 0 | `student_id`, `test_id` (PK пара), `finished_at`. Есть строка = тест завершён |

Представление `tasks_public` (`security_invoker=true`): `id`, `order_no`, `skill`, `dataset_id`, `statement_kk`, `answer_type`, `options`. Колонок с эталонами в нём нет.

Доступ: RLS включён на всех таблицах, политик нет. У `anon` и `authenticated` нет прав ни на одну таблицу и ни на `tasks_public`; права есть только у `service_role`. Функций в схеме `public` нет. Поэтому приложение читает базу только на сервере ключом `SUPABASE_SERVICE_ROLE_KEY`.

Чего нет в базе, хотя планировалось в черновике:
- **Ученики**: статус (активен / исключён), причина.
- **Задачи**: отдельные поля названия и сцены, текст на русском; есть только `statement_kk`.
- **Попытки**: класс, группа, номер попытки, вердикт. Вердикт `correct` или `incorrect` хранится в `is_correct`, время в `time_spent_ms`.
- Вопросов тестов в базе пока нет: строки в `test_questions` и `test_question_keys` положит автор (открытый вопрос 9 в ROADMAP.md).

## Состояние ученика на главной
Читает `lib/home.ts` на сервере по id ученика из cookie. Из `attempts` выбираются только `task_id` и `is_correct`, `answer_raw` не выбирается. В браузер не уходят id ученика и ответы.

- **Контрольный класс**: `classes.study_group = 'control'`, независимо от попыток. На главной только приветствие и блок тестов (или сообщение «тестов пока нет»), без пути, прогресса и ссылок на задачи. Страницы `/tasks/[orderNo]` для него отвечают 404, `POST /api/answer` — 403 (см. «Тесты»).
- **Первый вход**: экспериментальный класс, в `attempts` нет строк ученика. Приветствие, ссылка на задачу 1, путь, без прогресс-бара.
- **Повторный вход**: экспериментальный класс, есть хотя бы одна строка в `attempts`. Прогресс, ссылка на следующую задачу, путь.
- **Решённая задача**: есть попытка этого ученика с `is_correct = true`. Текстовая задача решённой пока быть не может: оценки появятся на шаге 7.
- **Отправленный вывод**: есть строка `attempts` этого ученика по текстовой задаче с `is_correct = null`.
- **Ждёт проверки**: вывод отправлен, оценки в `text_scores` нет. До шага 7 оценок нет, поэтому `lib/home.ts` смотрит только на `attempts`. На шаге 7 надо добавить чтение `text_scores`.
- **Прогресс**: решённые задачи из общего числа задач. Задачи 4 и 8 входят в общее число, но счётчик не увеличивают.
- **Следующая задача**: наименьший номер среди задач, которые не решены и не ждут проверки. Текстовая задача без отправленного вывода тоже может быть следующей. Если таких нет, вместо ссылки нейтральное сообщение.
- **Сбой чтения**: ошибка базы или подписанная cookie ученика, которого нет в базе, дают сообщение об ошибке, а не вариант «первый вход».

## Тесты
Тест — `pretest` (вводный) или `posttest` (итоговый), один набор вопросов для всех классов. Решение о состоянии принимает только сервер (`lib/tests.ts`), по классу ученика из базы; браузер к базе не обращается.

- **Открытый тест**: у класса ученика есть строка `class_tests` с `open = true`. По умолчанию (нет строки или `open = false`) тест закрыт. Интерфейса учителя пока нет, строки правятся вручную; переключатели — шаг 7.
- **Завершённый тест**: есть строка `test_sessions` ученика. Завершённый тест повторно пройти нельзя, даже если он ещё открыт.
- **Статус на главной**: завершён > открыт > закрыт, словом и значком («Аяқталды.», «Ашық.», «Жабық.»). Тест без вопросов на главной не показывается; если нет ни одного, контрольный класс видит «Әзірге тесттер жоқ.».
- **Страница** `/tests/[kind]` (`kind` = `pretest` или `posttest`, иначе 404): без сессии ведёт на `/login`. Закрытый и завершённый тест показывают только сообщение, вопросы не загружаются в ответ. Открытый: один вопрос на экране, варианты выбираются радиокнопками, переход по «Келесі», на последнем вопросе «Тестті аяқтау». Старт с первого вопроса без ответа. В браузер уходят текст вопроса, варианты и собственные сохранённые ответы ученика; id вопросов и ученика, эталон и признак верности не уходят.
- **Сохранение**: каждый ответ сохраняется сразу по нажатию «Келесі» (повторная отправка того же вопроса заменяет ответ), завершение — отдельным запросом. При обрыве связи или сбое остаётся тот же вопрос с сообщением, ответ повторяют. Уже сохранённое не теряется: после повторного входа (сессия 8 часов) тест продолжается с первого вопроса без ответа. Если тест закрыт во время прохождения, новые ответы отклоняются, сохранённые остаются.
- **Ограничение**: проверка «открыт, не завершён» и запись ответа — отдельные запросы к базе. Два одновременных запроса одного ученика могут записать ответ после завершения; на практике это возможно только при гонке двух вкладок.
- **Баллы**: пока не считаются и ученику не показываются. На шаге 7 учитель увидит результат; сравнение с `test_question_keys` делает сервер.

## Выводы
Вывод — непустой текст ответа на задачу с `answer_type = text` (задачи 4 и 8). Хранится в `attempts` без миграции: `answer_raw` — текст как он введён, `is_correct = null`. Каждая отправка пишет новую строку; какую оценивать, решается на шаге 7.

Текст вывода читает только сервер. Страница задачи узнаёт лишь да или нет (`hasSubmittedText` в `lib/answers.ts`, запрос без `answer_raw`), поэтому при новом открытии поле пустое. После отправки панель тоже очищает поле.

## Диаграмма
Связь задачи с диаграммой хранится в коде (`CHARTS` в `components/TaskChart.tsx`), миграции нет. Сейчас диаграмма одна: задача 4, столбцы по набору А. Значения читаются из `datasets.data`, поэтому совпадают с таблицей; строки без числа на диаграмму не попадают и названы в подписи под ней. Разницы, проценты и направление изменения диаграмма не показывает: это ответы задач.

## API
- `POST /api/answer` — серверная проверка ответа (`app/api/answer/route.ts`, логика в `lib/answers.ts`).
  - Нужна сессия. Без неё или с подделанной и просроченной cookie: 401 `{ "error": "unauthorized" }`.
  - Запрос: JSON `{ "orderNo": 1, "answer": "строка", "timeSpentMs": 1500 }`. `orderNo` — целое число, `answer` — строка, `timeSpentMs` — время от открытия страницы до отправки.
  - Ответ 200: только `{ "verdict": "..." }`. Вердикты: `correct`, `incorrect`, `invalid_format`, `teacher`.
  - Ошибки: 400 `{ "error": "bad_request" }` (не JSON или неверный `orderNo`), 403 `{ "error": "forbidden" }` (контрольный класс: задачи ему недоступны, класс берётся из базы, ничего не пишется), 404 `{ "error": "not_found" }` (нет задачи), 429 `{ "error": "rate_limited" }`, 500 `{ "error": "server_error" }`.
  - `number`: десятичный разделитель — запятая или точка; верно, если |ответ − эталон| ≤ `tolerance`, при пустом `tolerance` нужно точное равенство. Не число или пустая строка дают `invalid_format`. Пробелы внутри числа и запись вида `1e3` числом не считаются.
  - `choice`: значение не из `options` даёт `invalid_format`.
  - `text`: вердикт `teacher`, ответ сохраняется для учителя. Пустой текст, текст только из пробелов и текст длиннее 2000 знаков (`MAX_TEXT_LENGTH` в `lib/answers.ts`) дают `invalid_format`. В поле ввода тот же предел через `maxLength`.
  - Ответ API никогда не содержит эталон, допуск или рубрику.
  - `invalid_format` не считается неверной попыткой.
  - Запись попытки: `correct`, `incorrect` и `teacher` пишутся в `attempts` (у `teacher` `is_correct = null`), `student_id` берётся только из cookie. `invalid_format` не пишется. Если запись не удалась, ответ 500 без вердикта.
  - `time_spent_ms`: принимается целое от 0 до 86 400 000 (сутки), иначе пишется `null`.
  - Лимит: 30 запросов за скользящую минуту на ученика, считаются все запросы с сессией, включая `invalid_format`. Счётчик в памяти процесса (`lib/rate-limit.ts`), на Vercel у каждого экземпляра свой.
- `POST /api/test/answer` — сохранить ответ на вопрос теста (`app/api/test/answer/route.ts`, общая проверка в `lib/test-api.ts`).
  - Запрос: JSON `{ "kind": "pretest", "position": 1, "answer": "вариант из options", "timeSpentMs": 1500 }`. `student_id` из тела не читается: ученик определяется только по cookie.
  - Ответ 200: только `{ "ok": true }`. Верно или неверно не сообщается ни в ответе, ни после завершения.
  - Ошибки: 400 `bad_request` (не JSON, неверный `kind`, ответ не из вариантов), 401 `unauthorized`, 403 `closed` (тест закрыт), 404 `not_found` (нет теста или вопроса), 409 `finished` (тест уже завершён), 429 `rate_limited`, 500 `server_error` (запись не удалась, подтверждения нет).
  - Лимит: 30 запросов за скользящую минуту на ученика, отдельный счётчик от `/api/answer` (ключ `test:<id>` в `lib/rate-limit.ts`), считаются все запросы с сессией. Счётчик в памяти процесса.
- `POST /api/test/finish` — завершить тест (`app/api/test/finish/route.ts`). Запрос `{ "kind": "pretest" }`. Ответ 200 `{ "ok": true }` и строка в `test_sessions`. Те же 400/401/403/404/409/429/500; 409 `incomplete`, если есть вопрос без ответа.
- `POST /api/login` — вход ученика (`app/api/login/route.ts`, поиск в `lib/students.ts`).
  - Запрос: JSON `{ "classCode": "...", "personalCode": "..." }`.
  - Ответ 200: `{ "ok": true }` и cookie сессии.
  - Ошибки: 401 `{ "error": "invalid_credentials" }`, один и тот же ответ для неверного класса, неверного кода и неактивного класса; 500 `{ "error": "server_error" }`.
  - Лимита попыток входа нет.

## Вход
- Ученик: страница `/login`, код класса и личный код. Код класса сравнивается точно, личный код приводится к заглавным буквам.
- Сессия (`lib/session.ts`): cookie `session` вида `id.срок.подпись`, HMAC-SHA256 на `node:crypto`, ключ `SESSION_SECRET`. HttpOnly, SameSite=Lax, Secure в продакшене, срок 8 часов. Подделанная или просроченная cookie считается отсутствующей.
- Защита (`proxy.ts`): без сессии открыта только `/login`, всё остальное ведёт на неё. С сессией `/login` ведёт на `/`. Маршруты `/api` проверяют сессию сами. Страницы, которым вход не нужен (например `/teacher` на шаге 7), надо явно добавить в `proxy.ts`.
- Личные коды генерирует сайт, учитель печатает лист (шаг 7). Хранятся открытым текстом в `students.personal_code`, чтобы их можно было показать; браузер к базе не обращается.
- Учитель: `/teacher`, один секретный код из `TEACHER_SECRET_CODE`, без учётных записей.
