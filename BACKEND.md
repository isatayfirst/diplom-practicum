# BACKEND.md

Бэкенд: стек, модель данных, API, вход, экспорт.

## Стек
Next.js (App Router, TypeScript) + Supabase + деплой на Vercel.
Проект Supabase `practicum-mvp` уже существует: схема, RLS, `tasks_public` без ответов.

**ВАЖНО:** перед любой работой с базой в будущих шагах сначала осмотри существующие таблицы и RLS (только чтение). Ничего не пересоздавай. Изменения схемы только миграциями в `supabase/migrations`.

## Модель данных
Фактическая схема по осмотру базы 2026-11-05 (миграции `practicum_schema_v1`, `replace_sort_filter_with_functions`, `students_personal_code`, `classes_study_group`, `tests`, `students_status`). Число строк указано без тестовых данных приёмки.

Представление `tasks_public` (`security_invoker=true`): `id`, `order_no`, `skill`, `dataset_id`, `statement_kk`, `answer_type`, `options`. Колонок с эталонами в нём нет.

Доступ: RLS включён на всех таблицах, политик нет. У `anon` и `authenticated` нет прав ни на одну таблицу и ни на `tasks_public`; права есть только у `service_role`. Функций в схеме `public` нет. Поэтому приложение читает базу только на сервере ключом `SUPABASE_SERVICE_ROLE_KEY`.

Чего нет в базе, хотя планировалось в черновике:
- **Задачи**: отдельные поля названия и сцены, текст на русском; есть только `statement_kk`.
- **Попытки**: класс, группа, номер попытки, вердикт. Вердикт `correct` или `incorrect` хранится в `is_correct`, время в `time_spent_ms`.
- Вопросов тестов в базе пока нет: строки в `test_questions` и `test_question_keys` положит автор (открытый вопрос 9 в ROADMAP.md).

## Состояние ученика на главной
Читает `lib/home.ts` на сервере по id ученика из cookie. Из `attempts` выбираются только `id`, `task_id`, `is_correct`, `created_at`, `answer_raw` не выбирается; из `text_scores` читается только факт строки (балл не читается). В браузер не уходят id ученика, ответы и баллы.

- **Контрольный класс**: `classes.study_group = 'control'`, независимо от попыток. На главной только приветствие и блок тестов (или сообщение «тестов пока нет»), без пути, прогресса и ссылок на задачи. Страницы `/tasks/[orderNo]` для него отвечают 404, `POST /api/answer` — 403 (см. «Тесты»).
- **Первый вход**: экспериментальный класс, в `attempts` нет строк ученика. Приветствие, ссылка на задачу 1, путь, без прогресс-бара.
- **Повторный вход**: экспериментальный класс, есть хотя бы одна строка в `attempts`. Прогресс, ссылка на следующую задачу, путь.
- **Решённая задача**: есть попытка этого ученика с `is_correct = true`.
- **Отправленный вывод**: есть строка `attempts` этого ученика по текстовой задаче с `is_correct = null`. Считается последняя отправка по задаче.
- **Оценён**: у последней отправки вывода есть строка в `text_scores`. Статус на главной «Бағаланды» (по-русски «Оценена») одинаковый при любом балле 0, 1, 2: цифру и результат ученик не видит.
- **Ждёт проверки**: последняя отправка вывода без строки в `text_scores`. Новая отправка после оценки снова ждёт проверки.
- **Прогресс**: решённые задачи и оценённые выводы из общего числа задач. Оценённый вывод засчитывается при любом балле: иначе статус выдал бы ученику результат.
- **Следующая задача**: наименьший номер среди задач, которые не решены, не оценены и не ждут проверки. Текстовая задача без отправленного вывода тоже может быть следующей. Если таких нет, вместо ссылки нейтральное сообщение.
- **Сбой чтения**: ошибка базы или подписанная cookie ученика, которого нет в базе, дают сообщение об ошибке, а не вариант «первый вход».
- **Исключённый ученик** (`students.status = 'excluded'`): см. «Исключённый ученик» ниже.

## Тесты
Тест — `pretest` (вводный) или `posttest` (итоговый), один набор вопросов для всех классов. Решение о состоянии принимает только сервер (`lib/tests.ts`), по классу ученика из базы; браузер к базе не обращается.

- **Открытый тест**: у класса ученика есть строка `class_tests` с `open = true`. По умолчанию (нет строки или `open = false`) тест закрыт. Состояние меняет учитель в кабинете (раздел «Тесты»), по классу.
- **Завершённый тест**: есть строка `test_sessions` ученика. Завершённый тест повторно пройти нельзя, даже если он ещё открыт.
- **Статус на главной**: завершён > открыт > закрыт, словом и значком («Аяқталды.», «Ашық.», «Жабық.»). Тест без вопросов на главной не показывается; если нет ни одного, контрольный класс видит «Әзірге тесттер жоқ.».
- **Страница** `/tests/[kind]` (`kind` = `pretest` или `posttest`, иначе 404): без сессии ведёт на `/login`. Закрытый и завершённый тест показывают только сообщение, вопросы не загружаются в ответ. Открытый: один вопрос на экране, варианты выбираются радиокнопками, переход по «Келесі», на последнем вопросе «Тестті аяқтау». Старт с первого вопроса без ответа. В браузер уходят текст вопроса, варианты и собственные сохранённые ответы ученика; id вопросов и ученика, эталон и признак верности не уходят.
- **Сохранение**: каждый ответ сохраняется сразу по нажатию «Келесі» (повторная отправка того же вопроса заменяет ответ), завершение — отдельным запросом. При обрыве связи или сбое остаётся тот же вопрос с сообщением, ответ повторяют. Уже сохранённое не теряется: после повторного входа (сессия 8 часов) тест продолжается с первого вопроса без ответа. Если тест закрыт во время прохождения, новые ответы отклоняются, сохранённые остаются.
- **Ограничение**: проверка «открыт, не завершён» и запись ответа — отдельные запросы к базе. Два одновременных запроса одного ученика могут записать ответ после завершения; на практике это возможно только при гонке двух вкладок.
- **Баллы**: ученику не показываются. Результат X / N учитель видит в кабинете: сервер сравнивает ответы с `test_question_keys` (`lib/teacher.ts`), результат только у завершённых тестов, N — число вопросов теста.

## Выводы
Вывод — непустой текст ответа на задачу с `answer_type = text` (задачи 4 и 8). Хранится в `attempts` без миграции: `answer_raw` — текст как он введён, `is_correct = null`. Каждая отправка пишет новую строку. Оценивается **последняя** отправка ученика по задаче (по `created_at`); оценка пишется в `text_scores` по `attempt_id`. Оценка 0, 1 или 2, повторная заменяет прежнюю. Оценку более старой отправки сервер отклоняет (409). Оценка ученику не показывается.

Текст вывода читает только сервер. Страница задачи узнаёт лишь да или нет (`hasSubmittedText` в `lib/answers.ts`, запрос без `answer_raw`), поэтому при новом открытии поле пустое. После отправки панель тоже очищает поле.

## Диаграмма
Связь задачи с диаграммой хранится в коде (`CHARTS` в `components/TaskChart.tsx`), миграции нет. Сейчас диаграмма одна: задача 4, столбцы по набору А. Значения читаются из `datasets.data`, поэтому совпадают с таблицей; строки без числа на диаграмму не попадают и названы в подписи под ней. Разницы, проценты и направление изменения диаграмма не показывает: это ответы задач.

## API
- `POST /api/answer` — серверная проверка ответа (`app/api/answer/route.ts`, логика в `lib/answers.ts`).
  - Нужна сессия. Без неё или с подделанной и просроченной cookie: 401 `{ "error": "unauthorized" }`.
  - Запрос: JSON `{ "orderNo": 1, "answer": "строка", "timeSpentMs": 1500 }`. `orderNo` — целое число, `answer` — строка, `timeSpentMs` — время от открытия страницы до отправки.
  - Ответ 200: только `{ "verdict": "..." }`. Вердикты: `correct`, `incorrect`, `invalid_format`, `teacher`.
  - Ошибки: 400 `{ "error": "bad_request" }` (не JSON или неверный `orderNo`), 403 `{ "error": "forbidden" }` (контрольный класс: задачи ему недоступны, класс берётся из базы, ничего не пишется), 404 `{ "error": "not_found" }` (нет задачи), 429 `{ "error": "rate_limited" }`, 500 `{ "error": "server_error" }`.
  - `number`: десятичный разделитель — запятая или точка; верно, если |ответ − эталон| ≤ `tolerance`, при пустом `tolerance` нужно точное равенство. Не число или пустая строка дают `invalid_format`. Пробелы внутри числа и запись вида `1e3` числом не считаются.
  - `choice`: значение не из `options` даёт `invalid_format`.
  - `text`: вердикт `teacher`, ответ сохраняется для учителя. Пустой текст, текст только из пробелов и текст длиннее 2000 знаков (`MAX_TEXT_LENGTH` в `lib/answers.ts`) дают `invalid_format`. В поле ввода тот же предел через `maxLength`.
  - Ответ API никогда не содержит эталон, допуск или рубрику.
  - `invalid_format` не считается неверной попыткой.
  - Запись попытки: `correct`, `incorrect` и `teacher` пишутся в `attempts` (у `teacher` `is_correct = null`), `student_id` берётся только из cookie. `invalid_format` не пишется. Если запись не удалась, ответ 500 без вердикта.
  - `time_spent_ms`: принимается целое от 0 до 86 400 000 (сутки), иначе пишется `null`.
  - Лимит: 30 запросов за скользящую минуту на ученика, считаются все запросы с сессией, включая `invalid_format`. Счётчик в памяти процесса (`lib/rate-limit.ts`), на Vercel у каждого экземпляра свой.
- `POST /api/test/answer` — сохранить ответ на вопрос теста (`app/api/test/answer/route.ts`, общая проверка в `lib/test-api.ts`).
  - Запрос: JSON `{ "kind": "pretest", "position": 1, "answer": "вариант из options", "timeSpentMs": 1500 }`. `student_id` из тела не читается: ученик определяется только по cookie.
  - Ответ 200: только `{ "ok": true }`. Верно или неверно не сообщается ни в ответе, ни после завершения.
  - Ошибки: 400 `bad_request` (не JSON, неверный `kind`, ответ не из вариантов), 401 `unauthorized`, 403 `closed` (тест закрыт), 404 `not_found` (нет теста или вопроса), 409 `finished` (тест уже завершён), 429 `rate_limited`, 500 `server_error` (запись не удалась, подтверждения нет).
  - Лимит: 30 запросов за скользящую минуту на ученика, отдельный счётчик от `/api/answer` (ключ `test:<id>` в `lib/rate-limit.ts`), считаются все запросы с сессией. Счётчик в памяти процесса.
- `POST /api/test/finish` — завершить тест (`app/api/test/finish/route.ts`). Запрос `{ "kind": "pretest" }`. Ответ 200 `{ "ok": true }` и строка в `test_sessions`. Те же 400/401/403/404/409/429/500; 409 `incomplete`, если есть вопрос без ответа.
- `POST /api/login` — вход ученика (`app/api/login/route.ts`, поиск в `lib/students.ts`).
  - Запрос: JSON `{ "classCode": "...", "personalCode": "..." }`.
  - Ответ 200: `{ "ok": true }` и cookie сессии.
  - Ошибки: 401 `{ "error": "invalid_credentials" }`, один и тот же ответ для неверного класса, неверного кода и неактивного класса; 500 `{ "error": "server_error" }`.
  - Лимита попыток входа нет (известный риск шага 3; не закрыт на шаге 7).
  - Исключённый ученик (`status = 'excluded'`) получает тот же 401, что и при неверном коде; причина исключения ему не показывается.
- `GET /api/session-end` — стирает cookie `session` и ведёт на `/login`. Сюда страницы ведут исключённого ученика с ещё живой cookie (прямой переход на `/login` зациклился бы: `proxy.ts` отправляет вошедшего с `/login` на `/`).
- API учителя (все требуют cookie `teacher`, иначе 401 `{ "error": "unauthorized" }`; ответы без данных учеников):
  - `POST /api/teacher/login` `{ "code": "..." }` — 200 и cookie; неверный код (в том числе пустой и не строка) всегда 401 `invalid_credentials`; после 5 неверных за 15 минут с одного адреса 429 `rate_limited`, и верный код в это время тоже не принимается. Счётчик в памяти процесса (`lib/teacher-session.ts`), на Vercel у каждого экземпляра свой; адрес берётся из `x-forwarded-for`.
  - `POST /api/teacher/logout` — стирает cookie.
  - `POST /api/teacher/students` `{ "classId" }` — добавляет следующий номер (максимальный + 1) со сгенерированным личным кодом. 409 `class_full` (в классе 40), 404, 400.
  - `POST /api/teacher/students/exclude` `{ "studentId", "reason" }`, `reason` = `moved` / `class_changed` / `other`. 404, если ученика нет или он уже исключён; 400 при неверных значениях.
  - `POST /api/teacher/scores` `{ "attemptId", "score" }`, `score` — целое число 0, 1 или 2 (строка `"1"`, дробь, `null` — 400). 404 нет попытки, 400 попытка не по текстовой задаче или уже с вердиктом, 409 есть более новая отправка. Повтор заменяет оценку (upsert).
  - `POST /api/teacher/tests` `{ "classId", "kind", "open" }` — пишет `class_tests` для пары (класс, тест). 409 `no_questions` при открытии теста без вопросов, 404 нет класса. Подтверждение открытия итогового теста — окно на странице, не часть API.
## Вход
- Ученик: страница `/login`, код класса и личный код. Код класса сравнивается точно, личный код приводится к заглавным буквам.
- Сессия (`lib/session.ts`): cookie `session` вида `id.срок.подпись`, HMAC-SHA256 на `node:crypto`, ключ `SESSION_SECRET`. HttpOnly, SameSite=Lax, Secure в продакшене, срок 8 часов. Подделанная или просроченная cookie считается отсутствующей.
- Защита (`proxy.ts`): без сессии открыта только `/login`, всё остальное ведёт на неё. С сессией `/login` ведёт на `/`. Маршруты `/api` проверяют сессию сами. `/teacher` и вложенные страницы живут по своей cookie учителя (см. ниже): сессия ученика их не открывает, cookie учителя не открывает страницы ученика.
- Личные коды генерирует сайт, учитель печатает лист (шаг 7). Хранятся открытым текстом в `students.personal_code`, чтобы их можно было показать; браузер к базе не обращается.
- Учитель: `/teacher`, один секретный код из `TEACHER_SECRET_CODE`, без учётных записей. Форма кода — `/teacher/login`; без cookie `proxy.ts` ведёт на неё все страницы `/teacher/*`, а API учителя отвечают 401. Каждая страница и каждый API кабинета проверяют cookie сами (`lib/teacher.ts`), а не только `proxy.ts`.
  - Cookie `teacher` (`lib/teacher-session.ts`): `срок.подпись`, HMAC-SHA256 от `SESSION_SECRET` с меткой `teacher|` и самим кодом учителя в подписи. Cookie ученика кабинет не открывает; смена `TEACHER_SECRET_CODE` сразу гасит все сессии учителя. HttpOnly, SameSite=Strict, Secure в продакшене, срок 8 часов. «Шығу» стирает cookie.
  - Сравнение кода без утечки по времени: обе строки сворачиваются HMAC-ом одной длины и сравниваются `timingSafeEqual`.
  - Предел неверных кодов: 5 за 15 минут на адрес (см. API).
  - `TEACHER_SECRET_CODE` и `SESSION_SECRET` должны быть заданы; без них вход и проверка cookie учителя завершаются ошибкой, а не пропускают.
- Исключённый ученик: `lib/tests.ts → getStudentClass` вызывается на каждой странице и в каждом API ученика и бросает `InactiveStudentError` для `status = 'excluded'`. Страница ведёт на `/api/session-end` (cookie стирается), API отвечает 401. Cookie живёт до 8 часов, но исключённому она ничего не открывает уже со следующего запроса. Один дополнительный запрос на загрузку страницы.

## Кабинет учителя
Страницы (`app/teacher/(cabinet)/…`), класс выбирается в боковой панели и живёт в адресе `?class=<classes.code>` (по умолчанию первый класс по коду). Для контрольного класса есть только то, что на холсте T1B, T2B, T3B: тесты и список учеников без задач.

- **Итоги** `/teacher`: карточки (активные ученики, в среднем выполнено, в среднем попыток, больше всего попыток), тепловая карта, оценка выводов. Колонки задач берутся из `tasks`, а не зашиты. Контрольный класс: карточки по тестам и таблица результатов.
- **Тепловая карта**: таблица ученик × задача для **активных** учеников по `attempts` и `text_scores`. Ячейка: `none` (попыток нет), `unsolved` (есть попытки, верной нет), `solved` (есть верная), для выводов `pending` (последняя отправка без оценки), `scored` (последняя отправка оценена; учителю показывается балл). В ячейке число попыток (у выводов — все отправки). Колонка «Выполнено» = решённые + оценённые выводы. Цветная таблица для глаз (`aria-hidden`) и **текстовая версия** (`<details>`, те же значения словами, в атрибутах `data-state`, `data-attempts`, `data-score`) строятся из одних данных. Цвет не единственный признак: в цветной ячейке есть знак.
- **Карточки**: «в среднем выполнено» — среднее число выполненных задач на активного ученика; «в среднем попыток» — среднее число попыток по парам «ученик × задача», где попытка была; «больше всего попыток» — задача с наибольшей суммой попыток. Нет данных — тире.
- **Пустые данные**: нет учеников — сообщение со ссылкой на раздел «Ученики» и нулевая карточка; ученики без попыток — все ячейки «Басталмаған».
- **Оценка выводов** (секция на `/teacher`, на холсте экрана для неё нет): последняя отправка каждого активного ученика по текстовым задачам, текст вывода, выбор 0 / 1 / 2 и «Сақтау». Порядок списка не зависит от оценки. Текст вывода читает только кабинет (`lib/teacher.ts → loadAnswers`); рубрика не читается.
- **Ученики** `/teacher/students`: код класса, таблица номеров с личными кодами, статус и причина, результат вводного теста, число выполненных задач, дата последней попытки («Соңғы кіру» на холсте заменено: входы не пишутся), меню «⋯» → «Талдаудан шығару» в окне подтверждения с выбором причины. «Нөмір қосу» добавляет следующий номер (предел 40 в классе). Исключённые показаны приглушённо в конце таблицы; из карты, средних и результатов тестов они исключены, под картой заметка «Талдауға кірмейді: N». Кнопки «вернуть» нет (ошибочное исключение исправляется через SQL: `status = 'active'`, `excluded_reason = null`).
- **Классы** кабинет не создаёт (на холсте этого экрана нет): строки `classes` добавляются вручную (`code`, `label`, `study_group`, `active`).
- **Личные коды**: 5 знаков, генерирует сайт (`crypto.randomInt`), алфавит `ABCDEFGHJKMNPQRSTUVWXYZ23456789` (без 0, O, 1, I, L), уникальны внутри класса, хранятся открытым текстом.
- **Печать**: кнопка «Кодтарды басып шығару» вызывает `window.print()`; в `@media print` остаются заголовок, код класса и таблица «номер — код» активных учеников. Файлов и экспорта нет.
- **Тесты** `/teacher/tests`: переключатели `role="switch"` по классу, блок выгрузки CSV (см. «Экспорт CSV»), результаты X / N. Открытие **итогового** теста — через окно подтверждения; закрытие и работа с вводным — сразу. Переключатель меняется только после ответа сервера. Тест без вопросов открыть нельзя.
- **Окно подтверждения** (`components/teacher/ConfirmDialog.tsx`): нативный `<dialog>` с `showModal`, Tab и Shift+Tab замкнуты внутри окна, Esc закрывает, фокус возвращается на кнопку, из которой окно открыто (для меню «⋯» — на кнопку строки). Первым получает фокус «Бас тарту».
- Сервер читает данные ключом `SUPABASE_SERVICE_ROLE_KEY` в модулях `server-only`; эталоны задач и рубрика кабинету не нужны и не читаются, эталон теста (`test_question_keys`) используется только внутри подсчёта.

## Экспорт CSV
Три файла по классу на странице `/teacher/tests` (блок «Деректерді жүктеу (CSV)», пункт меню «Деректер экспорты» ведёт на него). Ссылки `<a download>` в виде кнопок. У контрольного класса два файла (попыток задач у него нет). Период только «барлық уақыт» / «за всё время»: выбора периода нет.

- **Эндпоинт** `GET /api/teacher/export/{attempts|tests|students}?class=<classes.code>` (`app/api/teacher/export/[kind]/route.ts`, сборка в `lib/export.ts`, формат в `lib/csv.ts`). Только по cookie учителя.
  - 401 `unauthorized` без cookie учителя (в том числе с cookie ученика); 400 `bad_request`: неверный вид файла или нет `class`; 404 `not_found`: неизвестный код класса; 403 `forbidden`: `attempts` у контрольного класса; 500 `server_error`. Метод только GET.
  - Заголовки: `Content-Type: text/csv; charset=utf-8`, `Content-Disposition: attachment` (`filename` ASCII-запасной и `filename*=UTF-8''…`), `Cache-Control: no-store`.
  - Имя файла: `<код класса>_<attempts|test-results|students>_all-time_<дата экспорта, UTC>.csv`; символы `\ / : * ? " < > |` и пробелы в коде заменяются на `_`.
- **Формат**: UTF-8 с BOM (`EF BB BF`), разделитель `;` (Excel с русской и казахской локалью делит по нему, запятую оставляет в одной колонке; R, pandas и SPSS читают `;` одним параметром), переводы строк CRLF (в том числе после последней строки). Ячейка с `;`, `"`, CR или LF берётся в кавычки, `"` удваивается. Текстовая ячейка, начинающаяся с `=`, `+`, `-`, `@`, табуляции или CR, получает впереди `'` (защита от формул). Числа только целые, десятичного разделителя нет. Дата и время: ISO 8601 в UTC без долей секунды, `2026-11-05T09:58:48Z`.
- **Подпись класса и периода**: в имени файла (код класса и `all-time`) и в каждой строке данных в колонках `class` (код класса) и `period` (текст периода на языке интерфейса). Строк-комментариев до заголовка нет: они ломают импорт в статистические пакеты. В файле без строк данных (пустой класс) подписи внутри нет, только в имени.
- **Заголовки и значения-перечисления** машиночитаемые (латиница, snake_case) и от языка не зависят; от языка зависит только значение `period`.
- **Файлы** (строки отсортированы по номеру ученика):
  - `attempts`: `student_no`, `class`, `period`, `task_no`, `attempt_no`, `verdict` (`correct` / `incorrect` / `teacher`), `score` (оценка вывода 0–2 у этой отправки; пусто, если не оценена или это не вывод), `time_ms` (пусто, если не записано), `created_at`. Одна строка на попытку, порядок: ученик, задача, время; `attempt_no` считается по паре «ученик × задача» (`invalid_format` в базе нет). Тексты выводов (`answer_raw`) в файл не входят и не читаются.
  - `tests`: `student_no`, `class`, `period`, `test` (`pretest` / `posttest`), `score` (число верных), `total` (число вопросов теста), `finished_at`. Только завершённые тесты (есть строка `test_sessions`).
  - `students`: `student_no`, `class`, `period`, `study_group` (`experimental` / `control`), `status` (`active` / `excluded`), `excluded_reason` (`moved` / `class_changed` / `other` или пусто).
- **Исключённые ученики**: в `attempts` и `tests` их строк нет (как нет их в карте и средних кабинета), в `students` они есть со статусом и причиной. Данные в базе не удаляются.
- **Чего в файлах нет**: имён, `personal_code`, id учеников, попыток и классов, `answer_raw`, текстов выводов, эталонов.
- **Не проверено**: открытие в Excel (проверяет автор).

## Язык интерфейса
Два языка: казахский (по умолчанию) и русский. Тексты только в `messages/kk.json` и `messages/ru.json`; наборы ключей совпадают, фраза без казахского перевода берётся из русского.

- **Выбор** хранится в cookie `lang` (`kk` или `ru`, path `/`, SameSite=Lax, 1 год, не HttpOnly, без личных данных). Любое другое значение даёт казахский. `<html lang>` равен выбору.
- **Переключатель** (`components/LangSwitch.tsx`): форма с двумя кнопками, у каждой `lang`, у текущей `aria-pressed="true"`. Работает без JS: `POST /api/lang` (поле формы `lang` = `kk` или `ru`) ставит cookie и отвечает 303 на страницу из `Referer` того же сайта (чужой или пустой `Referer` ведёт на `/`). Неверный язык: 400 `bad_request`, cookie не меняется. Вход не нужен: язык выбирают и на странице входа. Расположение: вверху страниц ученика (вход, главная, задача, тест), в боковой панели кабинета и на форме входа учителя.
- **Как `t()` узнаёт язык**: серверные компоненты берут `const t = await getT()` (`lib/messages.ts`, читает cookie); клиентские — `useT()` из `components/LocaleProvider.tsx`, словарь выбранного языка приходит с сервера в корневом layout. Общая часть без чтения cookie — `lib/t.ts`. Из-за чтения cookie в корневом layout все страницы динамические.
- **API не зависит от языка**: вердикты и коды ошибок — коды, не переводы. Единственный текст, зависящий от языка в ответах сервера, — значение колонки `period` в CSV.
- **Тексты задач и вопросов тестов** лежат в базе только на казахском (`statement_kk`, названия наборов данных): в русском интерфейсе они остаются на казахском (открытый вопрос 12 в ROADMAP.md).
